## 背景

README は信頼性と冪等性を Outbox 導入の目的としている。

## 記録する判断

README の M02 に記録された Outbox 非同期化を、業務データ変更と後続イベント処理の境界として扱う。

この ADR は既存資料・コードの判断を整理した遡及記録であり、今回の整備で新しい設計を承認・実装したものではない。設計資料にある将来案の実装完了は断定しない。

## 代替案と判断の根拠

上記の根拠資料に残る理由を記録する。比較した代替案・却下理由が資料にない場合は NEEDS_CONFIRMATION とし、後から選定経緯を作らない。

## 影響と制約

イベント再実行と重複処理に備え、consumer の冪等性と失敗時の復旧が必要になる。別 checkout の ORM 統合 ADR をこの checkout に移植したことにはしない。

## 再検討する条件

イベント契約・配送方式・ORM・トランザクション境界の変更。
